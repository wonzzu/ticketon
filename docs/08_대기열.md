# 08. 대기열

> **수만 명이 동시에 예매 버튼을 누를 때, 서버가 안 죽게 어떻게 줄을 세우는가.**
> 이 프로젝트의 간판 기능. Redis Sorted Set으로 순번을 매기고 정원만큼만 입장시키는 트래픽 평탄화를 설명한다.

---

## 1. 문제: 동시 진입을 그대로 받으면 죽는다

1만 명이 동시에 좌석 페이지·예매 API로 밀려들면 DB 커넥션이 마르고 서버가 터진다. 해법은 **줄을 세우는 것**:

```
[1만 명 동시 진입]
   ▼
대기열 (Redis) ── 1만 건은 Redis에만 쌓임 (DB 안 감)
   ▼ 정원(100명)만 통과
좌석 페이지 / 예매 ── 항상 ~100명만 실제 작업
```

뒤쪽(좌석·예매·결제)은 **항상 정원 이하**의 사람만 상대하므로 부하가 평탄해진다. 대기열이 DB 쓰기 부하의 댐 역할.

---

## 2. 자료구조 두 개: 대기줄 + 입장한 사람

[QueueService.java](../src/main/java/com/ticketing/queue/service/QueueService.java) — 회차(`scheduleId`)마다 Redis 키 3종:

| 키 | 타입 | 역할 |
|---|---|---|
| `queue:wait:{sch}` | **Sorted Set** | 대기줄. score=순번(작을수록 앞) |
| `queue:active:{sch}` | **Sorted Set** | 입장한 사람. score=만료시각(epoch ms) |
| `queue:seq:{sch}` | String(counter) | 순번 채번용 카운터 |

```java
private static final int CAPACITY = 100;                 // 동시 입장 정원
private static final long ACTIVE_TTL_MS = 10 * 60 * 1000; // 입장권 수명 10분
```
**왜 Sorted Set인가**: "먼저 온 순서대로"가 핵심이라 정렬이 필요하다. Sorted Set은 score로 자동 정렬되고, "앞에서 N명"(`range 0..N`), "내 등수"(`rank`)를 O(log N)에 뽑을 수 있다. 큐(선입선출)에 딱.

## 3. 진입 — 줄 서기

[QueueService.enter()](../src/main/java/com/ticketing/queue/service/QueueService.java)
```java
public QueueStatusResponse enter(Long scheduleId, Long memberId) {
    String member = memberId.toString();

    if (isActive(scheduleId, member)) return QueueStatusResponse.admitted();  // 이미 입장했으면 통과

    boolean already = redisTemplate.opsForZSet().score(waitKey, member) != null;
    if (!already) {                                       // 중복 줄서기 방지
        Long seq = redisTemplate.opsForValue().increment(seqKey(scheduleId));  // 순번 채번 (원자적 INCR)
        redisTemplate.opsForZSet().add(waitKey, member, seq);                  // 그 순번을 score로 줄에 추가
        redisTemplate.opsForSet().add(SCHEDULES_KEY, scheduleId.toString());   // "이 회차 대기열 활성" 등록
    }
    return status(scheduleId, memberId);
}
```
- `INCR`로 순번을 원자적으로 채번 → 동시에 들어와도 순번이 안 겹친다.
- `SCHEDULES_KEY`(`queue:schedules`)는 "지금 대기열이 돌아가는 회차들" 목록. 승급 스케줄러가 이걸 보고 어떤 회차를 처리할지 안다.

## 4. 내 순번 조회 — 폴링

[QueueService.status()](../src/main/java/com/ticketing/queue/service/QueueService.java)
```java
public QueueStatusResponse status(Long scheduleId, Long memberId) {
    if (isActive(scheduleId, member)) return QueueStatusResponse.admitted();   // 입장 완료

    Long rank = redisTemplate.opsForZSet().rank(waitKey, member);              // 내 앞 등수 (0-based)
    if (rank == null) return QueueStatusResponse.expired();                    // 줄에도 없고 입장도 아님
    Long total = redisTemplate.opsForZSet().zCard(waitKey);                    // 전체 대기 인원
    return QueueStatusResponse.waiting(rank, total);
}
```
응답 [QueueStatusResponse](../src/main/java/com/ticketing/queue/dto/response/QueueStatusResponse.java)는 세 상태:
- `ADMITTED`: 입장 완료 → 좌석 페이지로.
- `WAITING(ahead, total)`: 대기 중. 내 앞 `ahead`명 / 전체 `total`명.
- `EXPIRED`: 줄에서 사라짐(입장권 만료 등) → 재진입 안내.

프론트는 `GET /queue/{scheduleId}/status`를 **폴링**(기본 3초)하며 순번을 갱신한다. (SSE/WS는 추후 교체 여지)

엔드포인트 [QueueController](../src/main/java/com/ticketing/queue/controller/QueueController.java): `POST /queue/{scheduleId}/enter`, `GET /queue/{scheduleId}/status`. 둘 다 로그인 필요.

## 5. 승급 — 정원만큼 입장시키기 (스케줄러)

핵심 엔진. 3초마다 돌며 빈 자리만큼 줄 앞에서 끌어올린다.
[QueueService.doAdmit()](../src/main/java/com/ticketing/queue/service/QueueService.java)
```java
for (String sid : 활성_회차들) {
    // 1) 만료된 입장권 청소: score(만료시각) <= now 인 사람 제거
    redisTemplate.opsForZSet().removeRangeByScore(activeKey, 0, now);

    // 2) 남은 자리 계산
    long slots = CAPACITY - 현재_active_수;
    if (slots <= 0) continue;                              // 꽉 찼으면 패스

    // 3) 대기줄 앞에서 slots명 꺼냄
    Set<String> front = redisTemplate.opsForZSet().range(waitKey, 0, slots - 1);

    // 4) wait → active 이동 (입장권에 만료시각 부여)
    long expireAt = now + ACTIVE_TTL_MS;                   // 지금부터 10분
    for (String member : front) {
        redisTemplate.opsForZSet().remove(waitKey, member);
        redisTemplate.opsForZSet().add(activeKey, member, expireAt);
    }
}
```

설계 포인트:
- **입장권에도 수명이 있다(10분).** `active`의 score를 만료시각으로 두고, 매 사이클 `removeRangeByScore`로 만료자를 청소한다. 입장만 하고 잠수타는 사람이 자리를 영구 점유하는 걸 막는다.
- **빈 자리만큼만** 끌어올린다 → 뒤쪽 부하가 정원을 넘지 않는다.

## 6. 다중 서버 안전 — Redisson 분산락

스케줄러는 서버 인스턴스마다 돈다. 서버가 3대면 같은 회차를 3번 승급시켜 정원이 깨질 수 있다.
[QueueService.admit()](../src/main/java/com/ticketing/queue/service/QueueService.java)
```java
@Scheduled(fixedDelay = 3000)
public void admit() {
    RLock lock = redissonClient.getLock(ADMIT_LOCK);   // "queue:admit:lock"
    if (!lock.tryLock()) return;                       // 다른 인스턴스가 처리 중이면 양보
    try { doAdmit(); }
    finally { if (lock.isHeldByCurrentThread()) lock.unlock(); }
}
```
- `tryLock()` 실패 시 즉시 양보 → 한 번에 **한 인스턴스만** 승급 처리. 정원 정합성 보장.
- 이게 [07 §7](07_좌석선점_Redis.md)에서 언급한 Redisson 분산락의 실제 사용처다.

## 7. 예매와의 연결 — 대기열은 입장권 검사다

대기열 통과가 곧 예매 자격이다. [ReservationService.create()](../src/main/java/com/ticketing/reservation/service/ReservationService.java)
```java
if (!queueService.isAdmitted(dto.getScheduleId(), memberId))
    throw new BaseException(QUEUE_NOT_ADMITTED);   // 대기열 안 거쳤으면 예매 거부
```
[isAdmitted](../src/main/java/com/ticketing/queue/service/QueueService.java) = `isActive()` — `active`에 있고 아직 만료 안 됐는가.
```java
private boolean isActive(Long scheduleId, String member) {
    Double expireAt = redisTemplate.opsForZSet().score(activeKey, member);
    if (expireAt == null) return false;
    if (expireAt < System.currentTimeMillis()) {      // 만료됐으면
        redisTemplate.opsForZSet().remove(activeKey, member);  // 청소하고
        return false;                                  // 입장 아님 처리 (lazy 정리)
    }
    return true;
}
```
스케줄러의 일괄 청소(`removeRangeByScore`)와 별개로, 조회 시점에도 만료를 확인해 **lazy하게** 정리한다(이중 안전장치).

## 8. 전체 흐름 요약

```
POST /queue/{sch}/enter   → wait Sorted Set에 순번(INCR)으로 추가
GET  /queue/{sch}/status  → rank/total 폴링 (WAITING/ADMITTED/EXPIRED)
[스케줄러 3초]            → 분산락 → 만료 청소 → 빈 자리만큼 wait→active 승급
POST /reservations        → isAdmitted 검사 통과해야 예매 가능
```

---

## 9. 면접 한 줄 정리

> 대기열은 Redis **Sorted Set**으로 구현했습니다. `INCR`로 순번을 원자적으로 매겨 줄(`wait`)에 넣고, 3초 주기 스케줄러가 정원(100)만큼만 입장(`active`)시켜 뒤쪽 좌석·예매·DB 부하를 평탄화합니다. 입장권에 10분 TTL을 줘 잠수 점유를 막고, 스케줄러는 **Redisson 분산락**으로 다중 서버에서도 정원이 깨지지 않게 했습니다. 진입 1만 건은 Redis에만 쌓여 DB로 가지 않습니다.
